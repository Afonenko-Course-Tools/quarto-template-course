# Установленная проба порядка QRC → PDF → ZIP

`tests/probes/artifact-consumer.ts` продолжает исходную пробу пяти частей и
проверяет стыки новых Publisher и Print. Это доверенный технический пример P0,
а не готовый Core resource bridge или режим выпуска реального курса.

```sh
quarto run tests/probes/artifact-consumer.ts \
  --publisher /path/to/quarto-project-publish \
  --print /path/to/quarto-course-print \
  --core-export /path/to/quarto-course \
  --output /tmp/artifact-evidence
```

Для повторного запуска выбирайте новый каталог результатов: существующий
пользовательский cache отклоняется.

CI `.github/workflows/artifact-consumer.yml` использует точные companion commits
и повторяет установочную и отрицательную матрицу на Quarto `release` и
`pre-release`. Он не публикует сайт и не изменяет upstream repositories.
Для локального запуска Publisher и Print также берутся из указанных в workflow
commits: до слияния companion PR обычный `main` ещё не предоставляет этот API.

Core должен содержать экспериментальный производитель из companion PR #8
(commit `4f5caf9a15b9bd36476cad8a646e81521fbd29d1`). Нужны Quarto, CUE,
`tar`, `git`, Python 3 и Poppler (`pdftotext`, `pdfinfo`). Пакет учебного
содержимого получают заново из corpus/work-one/work-two через нативный
производитель и его CUE-проверки. Consumer получает только пакет, без импорта
исходников Core. Дерево исходного учебного corpus в публикацию не переносится.

Каждое расширение собирается в отдельный локальный source archive, устанавливается
через `quarto add`, после чего проверяется полный перечень файлов и SHA-256
каждого файла. Запрещены symlink в установленном дереве и его родительских
каталогах. Расширения шаблона сохраняют его namespace; самостоятельный Print
установлен как `course-print`. Исходники разработчика, Git и npm-зависимости не
попадают в consumer. Журнал сохраняет версии инструментов, companion commits,
признак dirty source и хеши именно проверенных файлов.

## Доверенная политика ресурсов

`fixtures/probes/artifacts/owner.ts` получает **явную fixture-политику** с
разрешёнными/запрещёнными профилями, source/target и SHA-256. Она не выводится из
`project-download.profiles`: ограничение ZIP не делает все исходники каталога
закрытыми. Политика привязана к хешам фиксированного `sourceRoot` данной попытки.

В `beforeRender` штатный `quarto inspect` раскрывает `files.resources` и
`files.configResources`. Возвращённый каталог проверяется вместе с потомками;
собственного обработчика glob нет. Дополнительно проверяется настоящий корень
внешнего native portal: его служебный snapshot уже существует после pre-render.
Проверка одного frozen snapshot не представляла бы этот поздний выбор root. Широкий `materials/**` и выбор родительского
каталога останавливаются до начала рендера members. Нативный Pandoc AST исходных
файлов дополнительно обнаруживает явную ссылку на запрещённый файл.

Нативная проба обнаружила дополнительный случай: `assets/**` выбирает также
вложенный `_extensions/course-print/assets`, а внешний root может выбрать assets
из `.project-publish/.../sources`. В fixture принят проверенный `./assets/**`;
возврат неограниченного glob теперь завершается ошибкой до members. Source/service
пути запрещаются также финальной проверкой; молчаливого удаления после копирования
нет. Это штатная семантика Quarto glob, не собственный matcher.

Последняя проверка просматривает реальные опубликованные файлы и ZIP через
Python `zipfile`, проверяя хеши запрещённых fixture-ресурсов. Поздняя копия под
другим именем останавливает выпуск. Служебные `_probe` и `_artifact-evidence`
отклоняются отдельно в обоих профилях; input-пакет с ключами запрещён также по
хешу при переименовании или попадании внутрь ZIP. Четыре короткие регрессии
`quarto run tests/probes/artifact-guards.ts` закрепляют найденную на ревью дыру:
проверка после commit публикации была слишком поздней. Публичный рисунок, использованный также в
закрытых заметках, остаётся доступным. Одинаковые basename из разных каталогов
не смешиваются. Для full действуют его разрешения той же fixture-политики.

**Граница:** это не полный нативный resource inventory. Консервативная проверка
авторских Link/Image не раскрывает все Quarto includes/профильную семантику и не
покрывает ресурсы после вычислений. Она может отвергнуть закрытую авторскую ссылку
даже в скрытом блоке. Production-решения о доступности и позднем AST остаются у
Core/resource bridge; fixture не заменяет CUE-вывод этих решений.

## Материализация и выдача

Порядок интеграций задаётся существующим массивом Publisher:

1. До members владелец проверяет frozen source snapshot.
2. QRC завершает настоящий `reference-catalog.json`.
3. Fixture-adapter связывает один нативный Link условия с текущим адресом QRC и
   вызывает установленный `renderPrint` с актуальным проверенным пакетом.
4. Только готовые PDF и выбранные публичные файлы вместе с целым starter project
   попадают в новый utility project. Его обычные project-download pre/filter/post
   собирают ZIP; внутренний request JSON и частные TypeScript функции не читаются.
5. Последняя проверка разрешённых ресурсов завершается до commit публикации.

Utility имеет `project.type: default`, не содержит учебных QMD, Core/book hooks,
QRC targets или вычислений. Её HTML отбрасывается. `gitignore:false` разрешает
упаковку нового generated staging, включая неупомянутые в ссылках `build.sh`,
`dependency.lock` и `src/main.txt`. Из Print не выдаются `public.json` и служебный
receipt. Ссылочные ресурсы остаются рядом с PDF с теми же относительными путями.
Дополнительный API или изменение схемы project-download не понадобились.

Проверяются точные bytes PDF внутри ZIP, состав/bytes starter и ссылочных
ресурсов, URL QRC в PDF-аннотации и отсутствие решений/ключей на бумаге. После
изменения условия или рисунка пакет получают заново. Удаление печатной цели
исключает её PDF/ресурсы из следующего выпуска; удалённый текущий PDF создаётся
заново. Отказ печати, упаковки или последней ресурсной проверки не оставляет
текущий частичный выпуск; другой профиль сохраняется.

Каждый render использует новый пользовательский cache и документированный
`QUARTO_RUN_NO_NETWORK=true` для импорта Deno. Это **не** утверждение об OS-level
сетевой изоляции Quarto/Typst и других дочерних процессов. Native root portal
может кратковременно существовать до post-render; удаление после ошибки не
доказывает полную изоляцию временного portal output.

`upstreamCurrent:true` здесь означает успешную текущую fixture-проверку и
завершённый QRC. Это доверенное утверждение caller, не самостоятельное
доказательство свежести произвольного JSON. Без закреплённого immutable toolchain
identity эта интеграционная проба компилирует новый PDF; selective reuse и его
матрица проверяются отдельно в репозитории Print. Общего scheduler здесь нет.
Существующий coordinator по-прежнему собирает всех выбранных members; эта проба
не доказывает адресное обновление HTML-книги после небольшой правки. Print не
запускает повторный render владельца ради изготовления PDF.

Исходная `installed-consumer.ts` и штатные `tests/check.ts`/`tests/external.ts`
остаются отдельными regression gates, включая обычные PDF книг, ссылки между
книгами и Reveal, source/issue, публичные notes и профили. Никакой PDF слайдов или
Beamer не добавляется. Реальные Moodle/PrairieLearn import/load и полный P0 этим
тестом не объявляются завершёнными.

Локальная полная матрица содержит 13 случаев. На проверенном host обычные
совместные выпуски заняли около 47–56 с, включая проверки, рендер всех пяти
members, portal, QRC и utility ZIP. Семь реальных материализаций выбранной
одностраничной работы заняли 0.56–0.70 с каждая. Это измерения конкретной
пробы, не бюджет 2–6 страниц и не обещание общей пересборки за 5 с.
