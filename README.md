# Шаблон учебного курса

Шаблон объединяет книгу, слайды лекций и практики, исследовательские работы и задания для учебных платформ. Сайт открывается на первой странице книги. Все части собираются из одного корневого проекта, сохраняют собственные настройки Quarto и могут ссылаться друг на друга.

## Быстрый запуск

Нужны актуальный Quarto и CUE. TypeScript и Lua запускаются средствами Quarto; отдельная установка Python, Node.js или Deno не требуется. Рабочий путь не должен содержать пробелы: это ограничение обработки команд сборки в Quarto. Кириллица допустима.

```sh
quarto render --profile student
quarto render --profile full
quarto preview --profile student --no-browser --port 4200
quarto run tests/check.ts
```

Профиль `student` используется по умолчанию. Результаты размещаются в `_site-student` и `_site-full`; публикуется студенческая версия. Исходники расширений входят в репозиторий и не скачиваются при сборке. Проект не зависит от имени репозитория, владельца или соседних каталогов.

## Устройство курса

| Каталог | Что демонстрирует |
|---|---|
| `book` | Главы, включаемые фрагменты, рисунок, задания и состав лабораторной |
| `lectures` | Слайды с прогнозом и обсуждением; раскрытие ответа при переходе вперёд |
| `practice` | Самопроверка и раскрываемое объяснение для самостоятельной работы |
| `essay` | Отдельная книга исследований, вложенные темы, указатели Quarto и контрольные задания |
| `essay/text/decoding/projects` | Стартовые проекты Gradle, авторские решения, обычные и мутационные тесты UTF-8 |
| `handouts` | Самостоятельный PDF-документ; отдельная сборка LuaLaTeX |
| `fixtures` | Локальный образец каталога независимой публикации |
| `tests` | Проверка результата сборки и покрытия возможностей других курсов примерами шаблона |

В книге список документов задаётся через `book.chapters`, в слайдах — через `project.render`. Количество занятий и нумерация глав не дублируются в собственной схеме. Идентификатор курса, видимость и проверка модели задаются обычным YAML:

```yaml
course:
  id: programming
  validate: true
  view: student
```

Поддерживается только текущий контракт расширений. Переключателей версий модели, старых форматов и автоматического преобразования устаревшей разметки нет. При обновлении расширений обновляют конфигурацию и примеры курса, затем проверяют обе сборки.

## Составной сайт и ссылки

Корневой `_quarto.yml` регистрирует подпроекты:

```yaml
reference-catalog:
  namespace: site
  home: book
  projects:
    book: {path: book, format: html}
    lectures: {path: lectures, format: revealjs}
    practice: {path: practice, format: revealjs}
    essay: {path: essay, format: html}
```

`home: book` размещает весь результат книги в корне сайта, вместе с оглавлением и поиском. Внешняя стартовая страница или перенаправление не требуются. Остальные части публикуются в одноимённых каталогах.

Внутри книги используются стандартные ссылки Quarto, например `@sec-contracts`. Между подпроектами — `@book:sec-contracts`, `@lectures:sec-contracts`, `@practice:sec-clamp` и `@essay:sec-essays`. Ссылки работают в обе стороны независимо от порядка рендера. Относительные адреса подходят для локального просмотра и GitHub Pages.

Публичные цели выбираются явно через `reference-catalog.exports`. В шаблоне наружу экспортируются выбранные главы книг. Внутренние ссылки на задания и слайды продолжают работать; ограничение экспорта не скрывает опубликованные страницы.

Импорт независимой публикации задаётся через `source`:

```yaml
reference-catalog:
  imports:
    os:
      source: https://example.edu/os/reference-catalog.json
      namespace: book
      base-url: https://example.edu/os/
      style: external
```

Ссылка `@os:sec-memory` получает название источника и внешний маркер. Источник JSON и адрес опубликованного сайта независимы. Допустимы HTTP(S), `file:` и путь к локальному каталогу. Для воспроизводимого автономного примера шаблон читает `fixtures/external-reference.json`; `example.edu` обозначает адрес, который автор заменяет своей публикацией. Импортированные цели повторно не экспортируются. Сетевые ошибки не подменяются старой копией каталога.

## Учебная разметка

Смысл элементов задаёт `course-core`, показ объяснений — `course-presentation`, управление слайдами — `course-navigation`, оформление — `bsu-theme`. Используются стандартные форматы `html` и `revealjs`.

В `book/topics/contracts` показаны цели, материалы, предварительные знания, ограничения, типичная ошибка, вывод, публичные критерии и результат сдачи. Задание обозначается `#exr-*`, связанное объяснение — `#sol-*` с атрибутом `for`. Подсказка остаётся обычным `callout-tip`. В лекции показаны прогноз и обсуждение; в практике — самопроверка. Учебный вопрос без `target` не становится оцениваемым заданием.

```qmd
:::: {#exr-example course-role="prediction" difficulty="introductory" time="2" work-mode="individual"}
## Прогноз

Что вернёт функция для совпадающих границ?
::::

::: {#sol-example for="exr-example"}
## Объяснение

Допустимый диапазон состоит из одного числа.
:::
```

`course-presentation.mode: lecture` раскрывает ответ очередным шагом слайда. В режиме `study` студент раскрывает его самостоятельно. Значение `time` — оценка времени, а не таймер. Печать раскрывает всё опубликованное содержимое.

Чтобы применить другую тему, удалите `metadata-files: [_bsu.yml]` и выберите обычную тему Quarto. Учебные элементы и ссылки сохранят поведение. Чтобы использовать штатное управление Reveal, удалите `course-navigation` из списка плагинов.

## Профили и закрытые материалы

Каждый подпроект содержит согласованные `_quarto-student.yml` и `_quarto-full.yml`; корневой координатор передаёт выбранный профиль всем частям курса.

```qmd
::: {.when-full}
Комментарий преподавателю и контрольное задание.
:::
```

`.when-full` сокращает стандартную запись `.content-visible when-profile="full"`; доступны также `.when-<profile>` и `.unless-<profile>`. Критерии преподавателя помещаются в `.grading-notes` и входят только в `full`. Фильтрация выполняется до извлечения учебной модели: скрытые задания отсутствуют в студенческом HTML, поиске, каталогах и архивах. Печать их не восстанавливает.

Открытый Git-репозиторий раскрывает исходники и историю. Закрытый банк заданий следует хранить в репозитории с подходящими правами доступа и публиковать из него только студенческий результат.

## Исследования и контроль

`essay` демонстрирует разделы книги, вложенные главы, общие фрагменты `include`, списки `categories`, семестр и сложность темы. Указатели строятся штатным механизмом `listing`; над таблицами уровни сложности названы по-русски. Машинные значения `introductory`, `intermediate`, `advanced` остаются частью контракта.

`course-pedagogy.document-defaults: true` переносит сложность и форму работы из метаданных документа на задания. Явный атрибут задания переопределяет значение по умолчанию. Предварительные знания описываются блоком `course-role="prerequisites"` и обычными ссылками.

Параметры контроля PrairieLearn находятся в `prairielearn.assessment-defaults`: число попыток, необходимое число выполненных заданий и способ назначения темы. Текст получает эти значения через штатный `meta`, поэтому условия не расходятся с настройками. Состав контроля задаётся `.assessment-items`.

Тема о UTF-8 содержит три независимых задания: построение контрпримера, разработка тестов и реализация декодера. Полная версия включает стартовые проекты, решения и закрытые проверки. Локальный запуск и назначение каждого набора описаны в `essay/text/decoding/projects/README.md`. Gradle и JDK нужны для учебных программ, но не для рендера курса; JUnit загружается Gradle при первом запуске тестов.

Книгу исследований собирают вместе с остальным курсом из корня репозитория: это необходимо для разрешения ссылок на другие подпроекты. Параметры назначения сохраняются в проверенной учебной модели; публикация заданий на платформе выполняется отдельно.

## Скачивание стартового проекта

```qmd
:::: {#exr-example target="manual" project="/projects/example"}
## Условие

{{< project-download exr-example >}}
::::
```

Архив формируется при сборке из содержимого `projects/example/student/`. В корне ZIP находятся инструкции, файлы сборки, заготовки и открытые тесты. Соседние `reference/` и `tests/` не попадают в архив. Вложенность главы и проекта не ограничена. Результат появляется в `_downloads` и исключён из Git.

`target="manual"` обозначает открытое упражнение. Только явный `target="prairielearn"` включает задание в соответствующий платформенный экспорт. Облачные задания используют `target="cloud"`; каждый шаг содержит обязательную проверку `phase="check"`. В лабораторной показаны два шага на разных ВМ, внешний файл проверки и проверка внутри документа.

`course.validate: true` проверяет модель CUE и останавливает сборку при повторном ID, неизвестном `target`, пропавшем проекте, неверном составе занятия или шаге без проверки. Архивы требуют проверенной модели. `course.validate: false` подходит только для издательской сборки без загрузок исходников.

## PDF-раздаточный материал

`handouts` — отдельный проект без HTML-результата:

```sh
quarto render handouts
```

Нужны LuaLaTeX и шрифты CMU Serif, CMU Sans Serif, CMU Typewriter Text с поддержкой кириллицы. Результат находится в `handouts/_output`. Пример показывает задания Quarto, перекрёстную ссылку, две колонки и переход на новую страницу. Он не включён в веб-сборку: автоматическая сборка и размещение PDF требуют отдельного этапа публикации.

## Обновление и проверка

Исходники в `_extensions/` и `<подпроект>/_extensions/` хранятся в Git как входные данные сборки. Их происхождение записано в `UPSTREAM.md`. Обновляйте расширения согласованно стандартным `quarto add` и коммитьте полученные каталоги целиком. Реализацию расширений меняют в их исходных репозиториях. Сборка не выполняет обновлений автоматически.

`quarto run tests/check.ts` собирает оба профиля и проверяет ссылки, каталоги, поиск, показ объяснений, отсутствие скрытых материалов и содержимое архивов. Для уже собранного сайта используйте `--skip-render`.

Чтобы проверить, что другой курс использует возможности, показанные в шаблоне:

```sh
quarto run tests/features.ts --course /path/to/course
```

Проверка извлекает возможности из настоящих документов и конфигураций обоих проектов. Новую авторскую разметку, расширение или настройку курса следует сначала продемонстрировать в шаблоне. Сравнение не заменяет рендер и проверку предметного содержания.

## GitHub Pages

1. Создайте репозиторий из шаблона.
2. В Settings → Pages выберите **GitHub Actions**.
3. Отправьте изменения в основную ветку или запустите процесс вручную.

GitHub Actions проверяет оба профиля с актуальными каналами Quarto `release` и `pre-release` и CUE. После успеха всей матрицы публикуется только `_site-student`, собранный стабильным Quarto. PR и еженедельные проверки ничего не публикуют. Права Pages выданы только заданию публикации; действия закреплены по SHA и обновляются через Dependabot.

Результаты рендера, кэши, архивы и результаты компиляции исключены из Git. Авторские HTML- и PDF-ресурсы допускаются. Если измените `output-dir`, добавьте новый каталог в `.gitignore`. Установленные расширения не исключаются из Git.
