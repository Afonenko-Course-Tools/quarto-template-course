# Документация инструментов Quarto

[Индекс спецификаций](spec/index.md) связывает действующие контракты с точными выпусками и сохранённой историей. Состояние сайта определяется Git SHA; версии компонентов и готовых групп закреплены в `Taskfile.yml` и `tests/ready-assets.json`.

Обычный Quarto website: последовательное руководство, страницы средств, справочник
и каталог готовых демонстраций. Автор курса начинает с `guide/index.qmd`;
этот README описывает сопровождение самого сайта.
Учебные примеры живут у производителей расширений; здесь их готовые результаты
получаются явно из закреплённых Releases. Основная ветка хранит только исходники
документации; `examples/` и `_site/` исключены из Git.

Требуются Quarto >=1.11.5, Task 3, curl и tar; для получения и проверки — Node.js.
Core 5.0.1 и текущие адаптеры используют CUE 0.17.1.
Для установки используйте точные команды `quarto add` из `Taskfile.yml`.

```sh
task install
task fetch
task render
task check
task preview
```

Каждая команда выполняет отдельный этап: `install` устанавливает закреплённый
bundle; `fetch` получает готовые группы; `render` создаёт `_site`; `check`
проверяет ссылки, поиск, навигацию, native source, точное копирование ресурсов
и копируемые authoring QMD через настоящий native book и выбранный Core;
`preview` открывает локальный просмотр.

После изменения Task-получения выполните `python3 tests/fetch.py`: регрессия
проверяет реальный Task/curl/tar в пути с кириллицей и пробелами и сохранение
прежней группы при отказе получения, неподходящем архиве, BUILD или hashes.

`fetch` проверяет SHA-256 архива до распаковки, затем точный BUILD commit,
sourceDirty:false, зависимости, source ref и SHA-256 каждого файла по `tests/ready-assets.json`.
Quarto-страницы ready групп должны иметь русский lang и source-действия
без дублей; vendor HTML остаётся неизменным.
Записи manifest, Task URL и source URL каталога относятся к одному producer
Release; при замене pins обновляются совместно по проверенным готовым assets.
Проверка не принимает просто непустые commit/dependencies. При отказе staging
прежняя готовая группа остаётся на месте.

`fetch` скачивает готовый HTML и ресурсы, не запускает языковые среды демонстраций.
`render` и `preview` не выполняют предварительную сборку примеров.
Windows использует PowerShell для операций с каталогами; macOS/Linux — штатные команды.
Локально проверена Linux-ветка; фактическое выполнение на Windows/macOS не подтверждено.

Публикация выполняется вручную, только после проверки: `task publish` вызывает
`quarto publish gh-pages --no-render`. Автоматического deploy workflow нет.
Публикуйте заново проверенное дерево чистого `main` с теми же pins/assets; PR workflow выполняет проверки. Фактическая публикация и live URL проверяются отдельно по [отчёту реализации](docs/releases/2026-10-08-implementation.md).

Структура исходников прежнего учебного шаблона доступна в истории Git и выпуске
`v1.0.0`. Руководство закрепляет Core `v5.0.1`, Publisher `v5.0.0`,
QRC `v3.0.0`, Print/Moodle `v0.3.0`, PrairieLearn `v5.0.0`, Cloud `v3.0.0` и Download
`v3.0.0`. Историческая Core ready-группа закреплена на `demo-20261008-1`; остальные семь готовых
групп используют неизменяемый `demo-20261008`. Source каждой группы соответствует
точному tool tag того же producer SHA. Авторская модель, схемы и Body API
сохраняют контракт Core 5. Старые aliases в текущую модель не переносятся.

Локальное изменение Core можно проверить отдельно до установки его выпуска:

```sh
python3 tests/guide-examples.py --core-source /path/to/quarto-course
```

Тест копирует выбранный Core в временную native книгу и читает буквальные
QMD из руководства. Он проверяет student/full, четыре сценария работ, пять
форм ответа, обе связи решений, все роли, время и selected Body; ready producer assets не пересобираются.
По умолчанию `task check` использует фактически установленный bundle из `task install`.
`node tests/site.cjs --documentation-only` проверяет только сайт объяснений;
полный check также проверяет все ready группы и буквальную авторскую разметку.

PR workflow устанавливает Quarto 1.11.5 и CUE 0.17.1 и выполняет проверки.
Он не публикует сайт. Publish сохраняет штатный gh-pages маршрут и выполняется
по проверенному main после обновления точных releases/assets.

Подготовка согласованного authoring обновления выполняется отдельно от публикации
этого сайта. Core 5.0.1, Download 3.0.0 и exporter 5.0.0 опубликованы. Platform
metadata 1.0.1 normal merged source и published OCI pins указаны в матрице;
source tag v1.0.1 ещё ожидается. Анонимный GHCR pull и проверенный Java
PR head остаются отдельными gates. Исторические готовые группы
в каталоге сохраняют прежние producer pins и не являются демонстрацией нового
full export. После фактических final pins обязательны whole installation,
буквальные guide tests, применимые export/grading проверки и exact-head review.
