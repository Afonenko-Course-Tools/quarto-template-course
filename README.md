# Programming Course Template

Шаблон учебного курса: HTML-книга, слайды лекций и практики, задания PrairieLearn и Cloud. Общий сайт открывается на первой странице книги; ссылки между всеми тремя частями разрешаются при сборке.

Рабочий каталог должен находиться в пути без пробелов: это ограничение разбора проектных hooks в Quarto 1.10/1.11. Кириллица допустима.

## Начало работы

Требуются Quarto ≥ 1.10 и CUE ≥ 0.17. Конкретный выпуск Quarto не закреплён. TypeScript и Lua запускаются средствами Quarto; отдельные Python, Node.js и Deno не нужны.

```sh
quarto render --profile student
quarto render --profile full
quarto preview --profile student --no-browser --port 4200
```

Исходники расширений уже включены: каталог ссылок — в `_extensions/`, ядро — в каждом подпроекте, Cloud и PrairieLearn — в `book/_extensions/`. Точные версии указаны в `_extension.yml` установленных копий. Коммитьте эти каталоги вместе с курсом. Сборка не скачивает расширения и не зависит от названия репозитория курса или его владельца. Репозиторий можно переименовать, переместить или создать из него форк.

## Содержимое

| Каталог | Назначение |
|---|---|
| `book` | Теория, задания, состав лабораторных и проекты для проверки |
| `lectures` | Слайды лекций Revealjs |
| `practice` | Слайды практики Revealjs |
| `_extensions`, `<подпроект>/_extensions` | Версионируемые исходники установленных расширений |
| `.github/workflows` | Сборка и публикация GitHub Pages |

Глава о контрактах включает задания из `_exercises.qmd`. Java-проект `clamp` демонстрирует PrairieLearn и отдельное открытое упражнение `target="manual"` со скачиванием исходников; проверка состояния двух ВМ — Cloud. Это примеры авторского формата; среды исполнения и компиляторы учебных платформ подключаются отдельно.

В книге `book.chapters` определяет включённые документы. У слайдов свой `project.render`. У каждого проекта сохраняются собственные настройки языка, оформления и нумерации. Количество занятий отдельно не объявляется.

## Главная страница

Корневой `_quarto.yml` содержит:

```yaml
project:
  type: website
  output-dir: _site-student
  render: []
filters: [reference-catalog]
reference-catalog:
  namespace: site
  home: book
  projects:
    book: {path: book, format: html}
    lectures: {path: lectures, format: revealjs}
    practice: {path: practice, format: revealjs}
```

`home: book` публикует весь результат книги в корне результата выбранного профиля, включая оглавление и поиск. В корне исходников нет внешнего `index.qmd`: первая страница книги находится в `book/index.qmd`. Слайды размещаются в `lectures/` и `practice/`.

Ссылки пишутся по смысловым ID: `@book:sec-contracts`, `@lectures:sec-contracts`, `@practice:sec-clamp`. Они работают в обе стороны и не зависят от порядка сборки. Относительные URL подходят для локального preview и GitHub Pages под именем репозитория.

## Проверка учебной модели

В `book/_quarto.yml` включено `course.validate: true`. Полная сборка книги проверяет модель CUE и останавливает публикацию при ошибках: пропавшем проекте, неизвестном target, повторном ID, неправильном составе занятия или облачном шаге без check.

Для чисто издательской сборки без архивов исходников можно установить `course.validate: false`; тогда CUE не вызывается. `project-download` требует проверенную модель и `course.validate: true`. Для отдельной работы с учебной моделью используйте минимальный пример соответствующего расширения. При общей сборке модель проверяется внутри изолированной сборки книги, временные данные затем удаляются.

## GitHub Pages

1. Создайте свой репозиторий из этого шаблона.
2. В Settings → Pages выберите **GitHub Actions**.
3. Отправьте изменения в `main` или запустите workflow вручную.

Workflow устанавливает Quarto актуального стабильного выпуска и CUE, собирает курс с расширениями из Git и явно собирает профиль `student` и публикует только `_site-student`. Бинарные результаты рендера в исходный репозиторий не коммитятся. Сам Quarto не привязан к patch-версии.

Каталоги `_site`, `_book`, `_output`, `_generated`, `.quarto` и `.qrc` создаются автоматически и исключены из Git. Содержимое `_site-student` можно также публиковать через ветку `gh-pages` или обычный статический сервер — содержимое первой страницы от способа публикации не меняется.

## Зависимости и Git

`_extensions/` и `<подпроект>/_extensions/` — входные данные сборки; они намеренно не внесены в `.gitignore`. Обновляйте их явно стандартной командой `quarto add` из нужного подпроекта и коммитьте изменение целиком. Для локального расширения передайте путь к его репозиторию, для опубликованного — адрес владельца, репозиторий и тег. Автоматического обновления при рендере или в CI нет.

Результаты рендера и кэши исключены `.gitignore` во всех подпроектах. Правила не запрещают все файлы `.html` или `.pdf`: авторские документы и ресурсы могут храниться в Git. Если измените `output-dir` на собственный каталог, добавьте его в `.gitignore`.

Файлы, уже добавленные в индекс Git, не перестают отслеживаться после изменения `.gitignore`. Для такого каталога результатов выполните `git rm -r --cached -- ПУТЬ_К_КАТАЛОГУ` и закоммитьте изменение; локальные файлы сохранятся.


## Видимость и профили

`student` выбран по умолчанию. Корневой координатор явно передаёт профиль книге, лекциям и практике. В каждом подпроекте есть `_quarto-student.yml` и `_quarto-full.yml` с согласованным `course.view`. Результаты находятся отдельно в `_site-student` и `_site-full`. Преподавательскую сборку не публикуют workflow GitHub Pages.

```qmd
::: {.when-full}
Комментарий и задание преподавателю.
:::
```

`.when-full` — сокращённый вариант `.content-visible when-profile="full"`; доступны общий `.when-<profile>` и `.unless-<profile>`. Разметка `.grading-notes` содержит критерии преподавателя и также включается только в `full`. Ядро фильтрует эти блоки перед извлечением модели, поэтому студенческий HTML, JSON, каталог ссылок, поиск и заявки на архивы не содержат скрытых заданий. Пример расположен в `book/topics/contracts/` и дополнен скрытыми комментариями в слайдах.

Видимость не ограничивает чтение Git: открытый репозиторий раскрывает исходники и историю, включая `_control.qmd`, `reference/` и закрытые тесты. Для закрытого банка контроля храните исходники в репозитории с соответствующим доступом и публикуйте только студенческий результат.

## Скачивание стартового проекта

```qmd
:::: {#exr-example target="manual" project="/projects/example"}
## Условие

{{< project-download exr-example >}}
::::
```

Архив создаётся при сборке из полного самостоятельного проекта `projects/example/student/`. Его содержимое становится корнем ZIP: инструкции, файлы сборки, заготовки и открытые тесты. `reference/` и закрытые `tests/` остаются рядом с `student/` и в архив не входят. Сам архив появляется в `_downloads` результата и не коммитится. Файлы проекта исключены из прямого копирования ресурсами Quarto. Вложенность главы и каталогов проекта не ограничена.

Shortcode не включает упражнение в PrairieLearn. Открытая демонстрация с `target="manual"` сохраняет этот target; платформенный экспорт выбирает только явные `target="prairielearn"`.

## Дополнительный подпроект

Книгу рефератов можно добавить в `essay/` как обычный Quarto book и зарегистрировать:

```yaml
reference-catalog:
  projects:
    essay: {path: essay, format: html}
```

У `essay/` должны быть собственный `_quarto.yml`, оба профиля и требуемые расширения. Каталоги внутри группируют общие темы; каждый реферат — отдельная глава. Семестр и сложность задаются метаданными, ключевые слова — списком `categories`, например `[Исключения, Ресурсы, Контракты]`. Числа в именах каталогов для нумерации не нужны: Quarto нумерует главы по оглавлению. Межпроектная ссылка имеет вид `@essay:sec-topic`.

## Проверка шаблона

`quarto run tests/check.ts` собирает `full` и `student`, проверяет локальные ссылки, каталог и поиск, отсутствие закрытого контроля в студенческой публикации и содержимое архивов. Для проверки уже собранного результата передайте `--skip-render`.
