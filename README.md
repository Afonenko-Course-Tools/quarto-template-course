# Programming Course Template

Шаблон учебного курса: HTML-книга, слайды лекций и практики, задания PrairieLearn и Cloud. Общий сайт открывается на первой странице книги; ссылки между всеми тремя частями разрешаются при сборке.

Рабочий каталог должен находиться в пути без пробелов: это ограничение разбора проектных hooks в Quarto 1.10/1.11. Кириллица допустима.

## Начало работы

Требуются Quarto ≥ 1.10 и CUE ≥ 0.17. Конкретный выпуск Quarto не закреплён. TypeScript и Lua запускаются средствами Quarto; отдельные Python, Node.js и Deno не нужны.

```sh
quarto render
quarto preview --no-browser --port 4200
```

Исходники четырёх расширений версии `1.0.0` уже включены: каталог ссылок — в `_extensions/`, ядро, Cloud и PrairieLearn — в `book/_extensions/`. Коммитьте эти каталоги вместе с курсом. Сборка не скачивает расширения и не зависит от названия репозитория курса или его владельца. Репозиторий можно переименовать, переместить или создать из него форк.

## Содержимое

| Каталог | Назначение |
|---|---|
| `book` | Теория, задания, состав лабораторных и проекты для проверки |
| `lectures` | Слайды лекций Revealjs |
| `practice` | Слайды практики Revealjs |
| `_extensions`, `book/_extensions` | Версионируемые исходники установленных расширений |
| `.github/workflows` | Сборка и публикация GitHub Pages |

Глава о контрактах включает задания из `_exercises.qmd`. Java-проект `clamp` демонстрирует PrairieLearn, проверка состояния двух ВМ — Cloud. Это примеры авторского формата; среды исполнения и компиляторы учебных платформ подключаются отдельно.

В книге `book.chapters` определяет включённые документы. У слайдов свой `project.render`. У каждого проекта сохраняются собственные настройки языка, оформления и нумерации. Количество занятий отдельно не объявляется.

## Главная страница

Корневой `_quarto.yml` содержит:

```yaml
project:
  type: website
  output-dir: _site
  render: []
filters: [reference-catalog]
reference-catalog:
  namespace: site
  home: book
  projects:
    book: {path: book, format: html}
    lectures: {path: lectures, format: revealjs}
    practice: {path: practice, format: revealjs}
```

`home: book` публикует весь результат книги в корне `_site`, включая оглавление и поиск. В корне исходников нет внешнего `index.qmd`: первая страница книги находится в `book/index.qmd`. Слайды размещаются в `lectures/` и `practice/`.

Ссылки пишутся по смысловым ID: `@book:sec-contracts`, `@lectures:sec-contracts`, `@practice:sec-clamp`. Они работают в обе стороны и не зависят от порядка сборки. Относительные URL подходят для локального preview и GitHub Pages под именем репозитория.

## Проверка учебной модели

В `book/_quarto.yml` включено `course.validate: true`. Полная сборка книги проверяет модель CUE и останавливает публикацию при ошибках: пропавшем проекте, неизвестном target, повторном ID, неправильном составе занятия или облачном шаге без check.

Для чисто издательской сборки можно установить `course.validate: false`; тогда CUE не вызывается. Для отдельной работы с учебной моделью используйте минимальный пример соответствующего расширения. При общей сборке модель проверяется внутри изолированной сборки книги, временные данные затем удаляются.

## GitHub Pages

1. Создайте свой репозиторий из этого шаблона.
2. В Settings → Pages выберите **GitHub Actions**.
3. Отправьте изменения в `main` или запустите workflow вручную.

Workflow устанавливает Quarto актуального стабильного выпуска и CUE, собирает курс с расширениями из Git и публикует только `_site`. Бинарные результаты рендера в исходный репозиторий не коммитятся. Для выпуска расширений используются теги `v1.0.0`; сам Quarto не привязан к patch-версии.

Каталоги `_site`, `_book`, `_output`, `_generated`, `.quarto` и `.qrc` создаются автоматически и исключены из Git. В `_site` можно также публиковать через ветку `gh-pages` или обычный статический сервер — содержимое первой страницы от способа публикации не меняется.

## Зависимости и Git

`_extensions/` и `book/_extensions/` — входные данные сборки; они намеренно не внесены в `.gitignore`. Обновляйте их явно стандартной командой `quarto add` из нужного подпроекта и коммитьте изменение целиком. Для локального расширения передайте путь к его репозиторию, для опубликованного — адрес владельца, репозиторий и тег. Автоматического обновления при рендере или в CI нет.

Результаты рендера и кэши исключены `.gitignore` во всех подпроектах. Правила не запрещают все файлы `.html` или `.pdf`: авторские документы и ресурсы могут храниться в Git. Если измените `output-dir` на собственный каталог, добавьте его в `.gitignore`.

Файлы, уже добавленные в индекс Git, не перестают отслеживаться после изменения `.gitignore`. Для такого каталога результатов выполните `git rm -r --cached -- ПУТЬ_К_КАТАЛОГУ` и закоммитьте изменение; локальные файлы сохранятся.
