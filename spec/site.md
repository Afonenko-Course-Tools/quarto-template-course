# Контракт сопровождения сайта документации

Репозиторий содержит обычный Quarto website. Исходники руководства хранятся в Git; готовые демонстрации принадлежат производителям и поступают из точных неизменяемых Releases, указанных в [Taskfile.yml](../Taskfile.yml). Их деревья копируются побайтно как native project resources. Рендер документации не пересобирает учебные примеры и не запускает их языковые среды.

`task install` устанавливает закреплённый bundle; `task fetch` получает восемь готовых групп; `task render` создаёт `_site`; `task check` проверяет ссылки, поиск, исходники и сохранение состава. `python3 tests/fetch.py` проверяет отдельную операцию получения. `examples/`, `.demo-staging/` и `_site/` являются локальным состоянием, не исходниками основной ветки. Текущие pins находятся в Taskfile того же ref; сведения BUILD не заменяют проверку файлов и producer provenance.

Документация описывает внешний контракт конкретного выпуска каждого владельца и ссылается на его спецификации. Правила Core/адаптеров здесь не объявляются повторно. Готовые демонстрации исключаются из общего поиска документации; source и repo links сохраняют нативную семантику Quarto.

Штатная публикация — `task publish`: сначала `task check`, затем `quarto publish gh-pages --no-render`. Исходники остаются в `main`, опубликованное дерево — в служебной `gh-pages`. Публикуется заново проверенное дерево чистого main с точными producer pins; факт существования команды не подтверждает состоявшуюся публикацию. Руководство закрепляет [контракты Core 5.0.1 и потребителей](../guide/specifications.qmd), а не переходный accepted-next документ.

[Отчёт реализации](../docs/releases/2026-10-08-implementation.md) фиксирует авторское покрытие, точные pins и фактическую проверку Pages. [Индекс](index.md) объясняет статус и связь версии с Git ref.
