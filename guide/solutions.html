Решения и публичные разборы

Сначала решите, нужна ли ссылка на разбор. В модели Core 4.0.1 есть две формы связи; у канонической задачи остаётся один контейнер решения.

Именованное решение для ссылки

Объявите задачу и решение в одном QMD с одинаковым суффиксом:

::: {#exr-lab-1 difficulty="introductory" time="20"}
Вычислите контрольную сумму полученного файла.
:::

::: {#sol-lab-1}
Выберите алгоритм, вычислите сумму и сравните её с доверенным значением.
:::

::: {.content-visible when-profile="full"}
После выполнения можно обратиться к @sol-lab-1.
:::

Связь exr-lab-1 → sol-lab-1 не требует дополнительного атрибута. В обычной open задаче student получает условие без решения; full видит оба. Ссылку на закрытый разбор не помещайте в открытый текст. Course-атрибут for у банковского решения больше не поддерживается.

Вложенное решение без ссылки

Используйте .solution внутри задачи, когда отдельный ID не нужен:

:::: {#exr-checksum-demo difficulty="introductory" time="10" course-role="demonstration"}
Покажите, как изменение одного байта влияет на контрольную сумму.

::: {.solution}
Вычислим SHA-256 исходного файла, изменим один байт и повторим вычисление.
Различие сумм обнаруживает изменение.
:::
::::

При open из метаданных банка это публичный разбор: student и full видят условие и решение. Именно роль demonstration открывает решение. Обычная open задача, роль standalone блока или stage demonstration сами такого права не дают.

Сохраните однозначную связь

Один связанный контейнер может содержать несколько подходов:

::: {#sol-lab-1}
### Через командную строку
Вычислите сумму штатной утилитой.

### Через программу
Прочитайте файл как байты и примените тот же алгоритм.
:::

Это замена содержимого решения из первого примера, а не второе объявление того же ID. Сирота sol-*, две подходящие пары, дубли и одновременно именованное и вложенное решение одной канонической задачи отклоняются.

В HTML Presentation сворачивает доступное решение; в Reveal использует details, в PDF/Typst показывает его статически. Профиль Core сначала определяет доступность, а затем Presentation оформляет оставшееся содержимое. Подсказка .callout-tip имеет свой смысл; допустимое for подсказки не меняет правило связи решения. Подробнее — представление.

Сделайте разбор переносимым для экспорта

Для demonstration, которую назначаете в экспортируемую работу, рекомендуются обычный suffix-контейнер или вложенная .solution без when-format/when-meta на самом контейнере решения. Такое решение переносится вместе с условием через выбранный native writer.

Форматное условие может оставить решение в HTML, но убрать его из публичной проекции исходного JSON-прохода. Тогда demonstration stage при экспорте честно отклоняется: требуется фактическое публичное решение текущей операции. Ранее собранный HTML не доказывает доступность в JSON. Дополнительный полный render, чтение старого результата или отдельный поиск решения не выполняются.
