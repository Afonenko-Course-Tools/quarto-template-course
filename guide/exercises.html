Задачи банка и обычные упражнения

Банк нужен для повторного назначения и выбранного экспорта. Обычный exr в книге или на слайде может оставаться обычным объектом Quarto. Ниже — модель Core 4.0.0.

Явно включите банк

# task/bank/_metadata.yml
exercise-bank: true
exercise-statement-visibility: open

Только #exr-* в области exercise-bank: true становится канонической задачей. По умолчанию банк выключен. Имя папки, формат книги и платформа не включают его. У каждой задачи обязательны собственные difficulty и time: introductory, intermediate или advanced; время — положительное целое число минут. Значения страницы или раздела эти поля не заменяют.

::: {#exr-collision difficulty="intermediate" time="25"}
Объясните различие между случайной коллизией и намеренным подбором.
:::

Результат — открытая задача средней сложности на 25 минут. Core отклонит её, если удалить собственное время, указать time="0", дробное время задачи или неизвестную сложность. Оценка времени относится к задаче; работа в паре задаётся позже на назначении.

Выберите публикацию условия

exercise-statement-visibility в нативных метаданных задаёт политику области. Атрибут statement-visibility конкретной задачи имеет приоритет:

::: {#exr-integrity-variant difficulty="intermediate" time="30" statement-visibility="restricted" course-role="control"}
Получены две версии журнала проверки. Укажите, какие изменения
можно обнаружить по сохранённым контрольным суммам.
:::

Эффективная политика обязательна: без метаданных области и без атрибута задачи объявление отклоняется. Скрытого open или restricted default нет. Роль control обозначает деятельность, но сама условие не скрывает.

Задача Student-сайт Full-сайт
open, обычная Условие; решение скрыто Условие и решение
open, course-role="demonstration", решение есть Условие и решение Условие и решение
restricted Условие, решение и ссылка назначения скрыты Условие и решение

Открытое условие не разрешает публиковать решение. Для публичного разбора нужна явная demonstration с решением. Stage работы свойства банковской задачи не меняет. Проверяется текущая декларация, без анализа Git или истории прежних публикаций.

Restricted условие можно выдать участнику выбранного Print/PrairieLearn экспорта. Это отдельная выдача участнику, а не публикация на открытом сайте; ключ, решение и заметки преподавателя остаются закрытыми.

Оставьте обычное упражнение вне банка

В самостоятельной странице, где банк не включён:

---
title: Обсуждение целостности
format: html
---

::: {#exr-observe}
Как понять, что файл изменился?
:::

::: {#exm-digest}
Сравнение хешей — пример проверки целостности.
:::

::: {#sol-observe}
Сравните текущую сумму с ранее сохранённой доверенной суммой.
:::

exr, exm, sol следуют Quarto: банковские difficulty/time и приватность к ним не применяются, в Course они автоматически не включаются. Нативный exm не становится банковской демонстрацией. Если нужно оформление, явно подключите filters: [course-presentation].

Добавьте платформенный проект

Для программной задачи привязка остаётся явной:

::: {#exr-java-digest difficulty="intermediate" time="45" statement-visibility="restricted" target="prairielearn" project="/projects/java-digest"}
## Подсчёт контрольной суммы

Допишите метод подсчёта SHA-256. Стартовые файлы находятся в проекте задачи.
:::

target и project не включают банк. Адаптер может требовать ведущий заголовок, структуру проекта и собственные настройки. Для PrairieLearn публичные стартовые файлы лежат в student, закрытые проверки — в tests, авторский вариант — в reference; весь каталог не становится веб-ресурсом. Экспорт и ресурсное владение проверяются отдельно.
