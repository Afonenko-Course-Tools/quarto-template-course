Поля ответа и закрытые ключи

Выберите форму ответа по смыслу задачи и возможностям потребителя. Разметка ниже относится к Core 4.0.1; банк уже включён, а каждая показанная задача имеет собственные difficulty/time и open default.

Текстовый ответ manual

:::: {#exr-explain difficulty="introductory" time="10"}
Объясните, почему контрольная сумма не устанавливает автора файла.

```{.yaml .answer-spec}
type: manual
submission: text
```

::: {.grading-notes}
В ответе должны быть разделены целостность данных и подтверждение авторства.
:::
::::

Публичная проекция содержит условие и поле «Ответ:». Преподавательские заметки извлекаются отдельно. Если специальный ответ не объявлен, Body использует manual с текстовым полем по умолчанию. Для явной структуры удобно оставить answer-spec.

Один вариант single-choice

:::: {#exr-choose difficulty="introductory" time="5"}
Что подтверждает совпадение суммы с доверенным эталоном?

::: {.answer type="single-choice"}
- [Совпадение проверяемых данных]{.correct}
- Авторство отправителя
- Наличие резервной копии
:::
::::

Нужны один BulletList, не менее двух вариантов и ровно одна .correct отметка на Span. Все варианты публичны; маркер правильного ответа скрывается и превращается в closedKey.correct. Этот индекс использует нумерацию с нуля во внутреннем payload; автор пишет отметку, а не индекс вручную.

Число numeric

:::: {#exr-size difficulty="introductory" time="5"}
Сколько байтов занимает 256-битный результат?

```{.yaml .answer-spec}
type: numeric
key:
  value: 32
  tolerance:
    absolute: 0
```
::::

Участник получает пустое поле «Ответ:». Значение и абсолютный допуск остаются ключом. Допуск должен быть неотрицательным числом; для приближённого значения можно явно указать, например absolute: 0.1.

Несколько частей multipart

:::: {#exr-parts difficulty="intermediate" time="15"}
Укажите размер результата и объясните, что проверяет его сравнение.

```{.yaml .answer-spec}
type: multipart
parts:
  - name: size
    label: Размер в байтах
    type: numeric
    key: {value: 32, tolerance: {absolute: 0}}
  - name: explanation
    label: Объяснение
    type: manual
    submission: text
```
::::

Поддерживаются части manual и numeric. У каждой уникальное name в форме ^[a-z][a-z0-9-]*$ и непустая авторская label. Метки и поля ответа публичны; numeric ключи остаются закрытыми. Авторские метки Core не переводит.

Соответствия matching

:::: {#exr-match difficulty="intermediate" time="10"}
Сопоставьте средство с его основным назначением.

```{.yaml .answer-spec}
type: matching
prompts:
  - Контрольная сумма
  - Цифровая подпись
options:
  - Проверка целостности
  - Подтверждение авторства
  - Хранение резервной копии
key:
  pairs:
    Контрольная сумма: Проверка целостности
    Цифровая подпись: Подтверждение авторства
```
::::

Prompts и options — непустые списки уникальных непустых строк. Ключ покрывает каждый prompt, ссылается только на известные options и не добавляет чужих prompts. Лишний вариант возможен. Участник получает условия, варианты и поле «Соответствия:»; пары ключа не выдаются.

Выберите поддерживаемый потребитель

Форма Core Print Moodle PrairieLearn текущей линии
manual Печатное поле essay Через программный проект с External grading
single-choice Варианты без correct multichoice с teacher ключом Не отдельный встроенный choice-экспорт
numeric Печатное поле Отклоняется Не отдельный встроенный numeric-экспорт
multipart Поля частей Отклоняется Не отдельный встроенный multipart-экспорт
matching Условия, варианты и поле соответствий Отклоняется Не отдельный встроенный matching-экспорт

PrairieLearn поставляет нативные вопросы с внешней проверкой: явный project, binding, стартовые файлы и закрытые tests. Наличие формы Core само по себе не создаёт встроенный PL-вопрос соответствующего типа. Cloud проверяет свою модель VM/действий и не является потребителем Body ответов.

Сохраните границу payload

condition и publicAnswer предназначены участнику. closedKey, solution и gradingNotes находятся отдельно в teacher пакете и отсутствуют в .public.json. Print/PrairieLearn получают participant-safe условие и ресурсы; Moodle использует нужный ему teacher ключ по своему контракту. visibility: public Body означает безопасную выдачу участнику, а statementVisibility: open|restricted — публикацию условия на сайте.

Не используйте answer-spec или grading-notes как обычный текст условия. Ключи и исходный YAML проверяются до student проекции, включая удаляемые restricted задачи. Публичный source modal исходной банковской страницы может раскрыть скрытый YAML — настройте исходники и ресурсы.
