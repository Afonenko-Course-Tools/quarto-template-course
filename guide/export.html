Экспорт выбранной работы

Экспорт получает назначения одной работы из полной исходной книги банка. Публикация full HTML для него не требуется. Назначения и restricted выдача определены контрактом Core 4.0.0.

Выберите корень, книгу и работу

В сценарии руководства логический корень объявляет course.id: integrity-course; native book находится в task, задачи включены явным exercise-bank, работа имеет assessment.id: checksum-lab. Из корня курса выполните команду по фактически установленному пути Core:

quarto run task/_extensions/Afonenko-Course-Tools/course-core/entrypoints/export.ts --book task --work checksum-lab --output _generated/checksum.json

--book . подходит, если корень сам является книгой банка. Функциональные варианты выбираются отдельно: --profile java,review. CLI требует одну книгу, одну работу и путь .json; student/full не передаются.

Публичный native source input включает задачи и работы выбранного проекта, в том числе QMD вне опубликованных chapters. Вложенные самостоятельные проекты с собственным _quarto.yml не входят. Quarto выполняет include, вычисления, shortcodes и функциональные профили; дополнительного Markdown парсера или предварительного full HTML нет. Неназначенная задача может не поддерживаться выбранным адаптером.

Внутренний JSON pass использует --fail-if-warnings=false: native предупреждение по междокументной ссылке само по себе не меняет exit 0 на отказ. После прохода Core проверяет актуальную модель, выбор и возможности Body. Публичные renders сохраняют свою строгую конфигурацию.

Прочитайте состав пакета

Создаются _generated/checksum.json для преподавательского потребителя и соседний _generated/checksum.public.json для участника. Исключите _generated из веб-ресурсов. Schema остаётся course-body-package-v1.

Поле Смысл
question owner, id, key, source Владелец, местный ID, квалифицированный ключ и источник
visibility: public Безопасная часть выдачи участнику
statementVisibility: open|restricted Публикация условия на сайте
purpose?, hasPublicSolution Факты текущего native прохода для проверки demonstration назначения
answerType, condition, publicAnswer Тип ответа, выбранное условие и публичные поля
teacher closedKey, solution, gradingNotes Отдельные закрытые поля
work items, assignments, theoryTime? Порядок, свойства назначений и время теории

Ключи works.items и assignments совпадают и квалифицированы одинаково: integrity-course/exr-collision. Значение назначения содержит {stage?, requirement, workMode}. Core локальная модель использует местные exr-* ключи; transport не является вторым авторским синтаксисом.

Экспортируются только выбранные условия, поля ответа и их ресурсы. Заголовок/ID работы сохраняются в метаданных. Preview, внешние заголовки этапов и окружающая проза исключаются; внутренние заголовки условия остаются. Обычная ссылка на разбор не выбирает его. Demonstration stage требует решения, сохранившегося в публичной native проекции этого JSON-прохода; доступность в ранее собранном HTML не подставляется. Переносимая форма не ставит when-format/when-meta на контейнер решения. QRC предоставляет адрес ссылки, без импорта чужого тела.

Restricted означает запрет открытой веб-публикации, но разрешает выбранную выдачу условия участнику. Public guards ключей, solution, gradingNotes, source/service ресурсов сохраняются. Не переименовывайте partitions публичных ресурсов в open/restricted: это другая граница.

Получите PDF-раздатку

Установите Print в корень курса, передайте participant пакет, полный ключ выбранной работы и новый каталог результата:

quarto run _extensions/Afonenko-Course-Tools/course-print/entrypoints/export.ts _generated/checksum.public.json integrity-course/checksum-lab _generated/paper

Print создаёт PDF через Pandoc/Typst из Quarto. Необязательный четвёртый аргумент — JSON оформления заголовка. В practical/test пакет содержит restricted назначения; публичный разбор из preview в PDF не попадает. Поддерживаемые формы ответа печатаются без ключей. Байты вложений, hash и безопасные targets проверяются до записи результата.

Получите Moodle XML

Установите Moodle. Для manual/single-choice сохраните binding.json с явными настройками:

{"defaultGrade": 1, "shuffle": false}
quarto run _extensions/Afonenko-Course-Tools/course-moodle/entrypoints/export.ts _generated/checksum.json binding.json _generated/questions.xml

Manual становится essay; single-choice получает teacher ключ и доли 100/0. defaultGrade — положительное конечное число, shuffle — boolean. Numeric/multipart/matching отклоняются. Solution и grading notes не входят в questiontext; вложения используют @@PLUGINFILE@@ после проверки bytes/hash. XML создаёт банк вопросов. Тест, расписание, попытки, доступ и подтверждённый импорт в реальный Moodle настраиваются отдельно.

Подготовьте PrairieLearn с внешней проверкой

Установите PrairieLearn вместе с Core в банк. Для упражнения нужны ведущий заголовок, явный проект и собственные платформенные настройки. Раскладка проекта:

projects/java-digest/
  student/     # стартовые файлы участника
  tests/       # закрытые проверки
  reference/   # авторский вариант, не поставляется

Каждый выбранный вопрос получает binding по местному ID q.id; это отдельная карта платформы, не qualified assignments:

{
  "questions": {
    "exr-java-digest": {
      "topic": "Java",
      "files": ["Digest.java"],
      "externalGradingOptions": {
        "image": "YOUR_VERIFIED_GRADER_IMAGE",
        "entrypoint": ["sh", "/grade/tests/grade.sh"],
        "timeout": 60,
        "enableNetworking": false
      }
    }
  }
}

Замените YOUR_VERIFIED_GRADER_IMAGE реальным проверенным образом вашей установки. topic задаёт тему; files — принимаемые файлы ответа, которые должны соответствовать выбранному стартовому проекту и проверкам. Опциональные entrypoint, timeout, enableNetworking, environment задаются явно по контракту адаптера.

quarto run task/_extensions/Afonenko-Course-Tools/course-prairielearn/entrypoints/export.ts . task java-lab binding.json _generated/pl

Поставка создаёт нативные вопросы gradingMethod: External, participant question.html, clientFilesQuestion из student и приватные tests. Reference не поставляется. Forms Core не превращаются автоматически во встроенные PL numeric/choice вопросы.

Если работе нужны PL правила, подключите их явно:

assessment:
  id: java-lab
  kind: lab
  prairielearn:
    attempts: 3
    pass: {at-least: 1}
    assignment: {mode: assessment-id}

Все назначения такой работы должны соответствовать target PrairieLearn. Attempts/pass/assignment описывают платформенную семантику; обязательность общего назначения не заменяется суммой баллов. Экспорт вопросов не создаёт activity и не назначает пользователей. Режим assessment-id получает устойчивую метку из course.id и assessment.id; применение метки — отдельное действие PL. Java/Gradle-группа содержит bindings, student, reference и настоящие локальные assertions. Они не подтверждают запуск image на сервере.

Cloud остаётся моделью действий

Cloud получает локальную модель Core и проверяет VM, cloud-step и cloud-action. Он не потребляет Body и не запускает VM, команды или экспорт _produced.yaml. Для него render и полная проверка свежего результата подтверждают структуру, а инфраструктурное исполнение проверяют в целевой среде отдельно.
