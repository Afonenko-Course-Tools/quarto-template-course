Педагогические роли

Роль поясняет смысл блока читателю. Она не задаёт баллы, платформу или форму выдачи работы. Примеры относятся к Core 4.0.1; для оформления подключите Presentation, для проверки — Core перед ним.

Выберите подходящий контекст

На канонической задаче допустимы роли деятельности: demonstration, discussion, independent-study, control. Остальные роли оформляют обычный Div вокруг или внутри задачи, страницы и описания работы. Все роли можно использовать в самостоятельных смысловых блоках. CSS-класс сам по себе не заменяет course-role.

Роль Контекст и рекомендация Результат
demonstration Разбор метода; на банковской задаче — явная демонстрация Подпись «Демонстрация»; публичное решение только у open задачи с решением
discussion Вопрос группе, standalone Div или задача банка Подпись «Обсуждение»
objectives Начало темы или работы Читатель видит цели
prerequisites Перед новым материалом Видны необходимые знания
reading Материалы темы, ссылки required/optional Отделены материалы для изучения
takeaway Итог темы или разбора Выделен главный вывод
limitation После описания метода Ясна граница применимости
misconception Разбор типичной ошибки Ошибка и объяснение видны рядом
criteria Описание работы либо внутренний блок задачи Ясны критерии результата
deliverables Описание сдаваемых материалов Ясно, что сдаёт участник
independent-study Самостоятельная деятельность, Div или задача Это роль деятельности; kind работы остаётся lab/seminar/practical/test
control Проверка освоения, Div или задача банка Подпись «Контроль»; публикацию определяет statement-visibility

Роли деятельности

Публичный разбор в банке с open default:

:::: {#exr-demonstrate difficulty="introductory" time="10" course-role="demonstration"}
Покажите сравнение двух контрольных сумм.

::: {.solution}
Сравните значения побайтно и зафиксируйте различие.
:::
::::

Вопрос для обсуждения:

::: {#exr-discuss difficulty="intermediate" time="15" course-role="discussion"}
Почему совпадение суммы не доказывает авторство файла?
:::

Самостоятельное изучение:

::: {#exr-self-study difficulty="intermediate" time="25" course-role="independent-study"}
Сравните два алгоритма по размеру результата и назначению.
:::

Контрольная деятельность:

::: {#exr-control difficulty="advanced" time="30" course-role="control" statement-visibility="restricted"}
Выберите достаточный способ проверки целостности для заданной угрозы.
:::

У каждого примера собственные difficulty/time. Для обсуждения вне банка можно взять обычный блок без экспортной задачи:

::: {course-role="discussion"}
Каким источникам контрольных сумм вы доверяете и почему?
:::

Цели, подготовка и материалы

::: {course-role="objectives"}
После занятия вы сможете проверить целостность файла и объяснить
ограничения такой проверки.
:::

::: {course-role="prerequisites"}
Нужно уметь читать файл как последовательность байтов и запускать программу.
:::

::: {course-role="reading" requirement="required"}
Прочитайте раздел о контрольных суммах до лабораторной.
:::

::: {course-role="reading" requirement="optional"}
Дополнительно сравните контрольную сумму и цифровую подпись.
:::

requirement здесь характеризует материал для чтения. Обязательность назначения задачи в работе задаётся отдельно на Span ссылки в .task-items.

Выводы и ограничения

::: {course-role="takeaway"}
Сравнивайте результат с доверенным эталоном.
:::

::: {course-role="limitation"}
Контрольная сумма обнаруживает изменение, но не устанавливает автора.
:::

::: {course-role="misconception"}
Совпавшая сумма не означает, что сам источник эталона надёжен.
:::

Используйте эти блоки рядом с объяснением метода. Они не становятся задачами, не получают банковское время и не входят в состав работы по роли.

Критерии и сдаваемые материалы

::: {course-role="criteria"}
Результат воспроизводим; объяснение различает целостность и авторство.
:::

::: {course-role="deliverables"}
Сдайте программу, пример входных данных и краткое объяснение результата.
:::

Публичные критерии можно оставить внутри условия. Закрытые инструкции проверки помещайте в .grading-notes внутри задачи — границы ответа. Роль criteria не превращает текст в закрытый ключ.

Для standalone деятельности Presentation может использовать явно включённые course-pedagogy.document-defaults страницы. В банке такой default не заменяет собственные difficulty/time. Вспомогательные роли цели/материалов/критериев оценку деятельности не наследуют. Полный словарь и контексты принадлежат Core.
