Работы, назначения и время

Состав работы — упорядоченные местные ссылки на банк. Один QMD описывает одну лабораторную, семинар, практическую или контрольную работу. Ниже — контракт Core 5.0.2.

Подготовьте общий банк для сценариев

Примеры используют книгу task с bank/_metadata.yml:

exercise-bank: true
default-exercise-statement-visibility: open

В bank/integrity.qmd поместите условия и решения:

# Целостность данных {#sec-integrity}

:::: {#exr-checksum difficulty="introductory" time="10" course-role="demonstration"}
Покажите изменение SHA-256 после замены одного байта.

::: {.solution}
Сначала вычислим исходную сумму, затем изменим байт и повторим вычисление.
:::
::::

::: {#exr-collision difficulty="intermediate" time="25"}
Объясните отличие случайной коллизии от намеренного подбора.
:::

::: {#sol-collision}
Случайное совпадение возникает без выбранной цели; намеренный подбор
ищет входы с требуемым совпадением.
:::

::: {#exr-repair difficulty="advanced" time="40"}
Предложите проверку повреждённого архива при наличии резервных данных.
:::

::: {#sol-repair}
Сравните доступные копии с доверенным эталоном и восстановите проверенную копию.
:::

::: {#exr-integrity-variant difficulty="intermediate" time="30" statement-visibility="restricted"}
## Проверка журнала
Какие изменения журнала можно обнаружить по сохранённым контрольным суммам?
:::

::: {#sol-integrity-variant}
Можно обнаружить изменение тех данных, для которых сохранён доверенный эталон.
:::

Student видит три открытых условия и решение checksum; restricted условие и остальные решения скрыты. Full видит все условия и решения.

Лабораторная без stage

Для лабораторной по программированию без разделения по месту выполнения создайте works/lab.qmd:

---
assessment:
  id: checksum-lab
  kind: lab
---

# Лабораторная по контрольным суммам {#sec-checksum-lab}

::: {course-role="deliverables"}
Сдайте программу сравнения сумм и объяснение выбранного алгоритма.
:::

::: {.task-items requirement="required" work-mode="pair"}
1. @exr-collision
2. [@exr-repair]{requirement="optional" work-mode="individual"}
:::

Stage может отсутствовать: скрытого classroom нет. Вид lab не задаёт платформу или оценку. Student/full показывают ссылки на оба открытых условия; доступ к решениям определяется банком. Экспорт содержит collision, repair и их поля ответа, но не внешнее описание сдачи.

Семинар с тремя этапами

В works/seminar.qmd используйте название и ID первого заголовка:

---
assessment:
  kind: seminar
  theory-time: 15
---

# Семинар по целостности данных {#sec-integrity-seminar}

## Разбор с преподавателем

::: {.task-items stage="demonstration"}
1. @exr-checksum
:::

## В аудитории

::: {.task-items stage="classroom"}
1. [@exr-collision]{work-mode="pair"}
:::

## После занятия

::: {.task-items stage="homework"}
1. [@exr-repair]{requirement="optional" work-mode="group"}
:::

ID работы здесь sec-integrity-seminar; вместо него можно явно задать assessment.id: integrity-seminar или использовать существующий chapter-id. Несколько списков объединяются в порядке документа: checksum, collision, repair. Заголовки — штатный способ описать последовательность занятия.

На .task-items задаются общие requirement="required|optional" и work-mode="individual|pair|group"; Span конкретной ссылки может их переопределить. Приоритет: Span → .task-items → required/individual. В лабораторной выше collision наследует required/pair, repair переопределяет оба поля на optional/individual. Это свойства назначения, а не самого упражнения. Stage задаётся только блоку списка, может отсутствовать и не выводится из заголовка; скрытого classroom нет. [@exr-collision]{stage="classroom"} отклоняется как ошибочное размещение stage на Span. Каждый пункт содержит одну местную ссылку. Повтор задачи в пределах одной работы отклоняется; в разных работах её можно назначать снова.

Для demonstration обязательны три факта банка: открытое условие, роль demonstration и фактическое публичное решение. Удаление любого из них делает первое назначение ошибкой. Stage не открывает закрытое решение. Проверяется фактическая публичная проекция текущей операции: решение, видимое в прежнем HTML, может отсутствовать в исходном JSON из-за when-format/when-meta. Для экспортируемого разбора используйте переносимый контейнер решения.

Student/full показывают состав семинара; student видит публичный разбор checksum. Экспорт содержит три условия в том же порядке, без внешних заголовков этапов и без решений. Внутренний заголовок самой задачи сохраняется.

Практическая на распечатках рядом с lab

Это отдельный QMD works/practical.qmd с собственным видом работы:

---
assessment:
  id: integrity-practical
  kind: practical
---

# Практическая работа на распечатках {#sec-integrity-practical}

::: {.assessment-preview}
Работа проводится в аудитории. Перед занятием изучите разбор @exr-checksum.
Понадобится объяснить причины, а не только записать итоговый ответ.
:::

::: {.task-items stage="classroom"}
1. @exr-integrity-variant
:::

В practical назначаются только restricted задачи. Student показывает название и preview без закрытой ссылки назначения; full также позволяет перейти к полному условию и решению. Выбранный participant-экспорт выдаёт только integrity-variant с полем ответа. Открытый разбор, preview и его ресурсы в раздатку не включаются. PDF — способ выдачи, а practical — вид работы.

Контрольная и экзамен

В works/test.qmd:

---
assessment:
  id: integrity-test
  kind: test
---

# Контрольная по целостности данных {#sec-integrity-test}

::: {.assessment-preview}
Проверяются выбор метода и понимание его ограничений.
Образец рассуждения: @exr-checksum.
:::

::: {.task-items}
1. @exr-integrity-variant
:::

Экзамен тоже использует kind: test. В test разрешены только restricted назначения; публичные примеры идут обычными ссылками в preview. Student/full и экспорт ведут себя как в practical. .assessment-preview виден на обеих версиях сайта и полностью исключён из экспорта; он не назначает задачи и не меняет политику банка. Отдельного профиля для preview нет.

Прочитайте четыре итога времени

Итог семинара Расчёт Минуты
Задачи required checksum + collision 35
Задачи all checksum + collision + repair 75
Занятие required задачи required + теория 50
Занятие all задачи all + теория 90

assessment.theory-time: 15 показывается отдельно и добавляется один раз к каждому итогу занятия. Это время теории вне уже учтённых задач. Допустимо положительное конечное число, например theory-time: 7.5; тогда два итога семинара будут 42.5 и 82.5. Собственное time задачи остаётся целым. Demonstration включается в суммы; pair/group их не масштабируют. Обычная ссылка в preview не включает время примера автоматически.

Полный render/экспорт проверяет состав по полной текущей модели. Частичный render или preview может пропустить недоступный итог либо показать ??. Это повод проверить полный текущий запуск. Частичная сумма, ноль или старый sidecar не заменяют полный итог; дополнительный полный render ради preview не выполняется.

Экспорт поясняет разделение participant и teacher пакетов.

Свяжите защиту с постановкой

assessment:
  kind: test
  related-exercise: exr-essay-integrity

Related exercise должен существовать как конкретная manual independent-study постановка. Presentation выводит связанную тему; ручную дублирующую ссылку не добавляйте. .task-items сохраняет порядок трёх проверяемых заданий, required и individual по умолчанию. При policy pass-at-least2 fully completed считаются два required вопроса; partial points не заменяют завершённый вопрос. Способ выбора, approval и доступ определяется server Gateway отдельно от body.
